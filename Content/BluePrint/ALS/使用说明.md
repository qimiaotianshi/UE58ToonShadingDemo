# DreamBloom 跑图物理与脚步优化（Locomotion70 / 插件 1.40）

## 本次物理与滑步优化
ABP_ALSLocomotion 的 KawaiiPhysics：Simulation Space=Component Space，Physics Settings/World Damping Location=1，World Damping Location Rate by Bone Length Rate 曲线清空。保留原 World Damping Rotation（0.9）与动画姿势、重力和身体碰撞；世界平移不再拖拽裙摆/头发。无需修改 KawaiiPhysics 插件源码。
BS_ALSLocomotion 的 Play Rate 绑定 UWardrobeLocomotionAnim.LocomotionPlayRate；根据实际角色速度/当前混合的源动画步速计算，移动速度160/420保持不变。
DA_ALSLocomotion 新增 Walk Animation Speed（107.30cm/s）和 Run Animation Speed（300.67cm/s），表示动画在1倍速时的步速，不是角色移动速度。若替换动作可调整它们。数值调大，动画步频会降低；调小，步频提高。
Animations 的 Idle/Walk/Run 增加 ALS_FootPlant_L/R 曲线，WardrobeFootIK 在落脚阶段锁定脚的世界XY，抬脚释放，并限制最大锁定距离、转身释放，避免脚被留在身后。原来的地面高度/斜坡IK仍然工作。只有ALS动画蓝图启用 Foot Lock，角色展示动画蓝图默认关闭。
物理对照测试：相同姿势连续平移1260cm，局部物理骨骼差异0.0000cm。
平地落脚对照：走路平均水平滑动速度30.752→0.588cm/s，跑步34.356→0.271cm/s（锁定前后，当前样例）。复杂地形与急转弯仍依赖地面碰撞和动作质量，不能保证所有动作完全无滑步。
本机9项回归测试通过；实际走跑画面、展示到跑图并返回流程已验证。
从68或69更新时，关闭UE后覆盖同名 Plugins/DreamBloom 与 Content/BluePrint/ALS。

## 保留的坐标修正
模型与待机、走路、跑步 FBX 均从 Blender 按 Forward=X、Up=Z 重新导出；UE 导入开启 Convert Scene、Force Front X Axis、Convert Scene Unit，Import Rotation 为零。
同时修正 ALS_Root 烘焙时忽略静置旋转的问题，移除角色网格原来的 -90 度额外朝向补偿，并重建脚底 IK 接触数据。
模型保持约155厘米身高，模型与动画使用一致的单位转换。Blender Apply Scalings 使用 All Local（FBX_SCALE_NONE），避免旧导入设置把网格缩成1/100。
已更新 SourceAssets 中的 Daniya_ALS.blend、SK_DaniyaALS.fbx 和 A_ALS_Idle/Walk/Run.fbx。原始 Blender 工程没有覆盖。

## 配置
- Data/DA_ALSLocomotion：Walk Speed、Run Speed、Acceleration、Braking、Turn Speed、Blend Time、Camera Distance、Locomotion Blend Space。
- AnimationBP/BS_ALSLocomotion：横轴 Gait，0=待机，1=走路，2=跑步。替换样本时使用 SK_DaniyaALS_Skeleton 兼容动画。
- Animations/A_ALS_Idle、A_ALS_Walk、A_ALS_Run：分别来自 Stand01、Fuyong/Walk_F、Fuyong/Run_F；已转为原地动画。
- Character/BP_ALSCharacter（实际目录 Characters）：角色模型、动画蓝图、胶囊和相机组件。
- AnimationBP/ABP_ALSLocomotion：BlendSpace → 脚部 IK → KawaiiPhysics → 最终姿势。
- Input/IMC_ALS：改按键。第一版没有跳跃、翻越、战斗、联网。
- SourceAssets：新的 Blender 文件、模型/动作 FBX 和 PNG 源图；原始 Blender 工程没有覆盖。

## 迁移到其他工程
1. 关闭目标 UE，备份目标 Plugins/DreamBloom 和本次会更新的 Content。
2. 复制本包 Plugins/DreamBloom 与 Content/BluePrint/ALS 到目标工程的同名路径。不要把 Source 又套进 Source。
3. 启用 DreamBloom、EnhancedInput、KawaiiPhysics。目标需要现有兼容的 KawaiiPhysics；这个包不修改 KawaiiPhysics 源码。
4. 若目标用自改源码引擎，不复用本包官方 UE5.8 DLL。移开/删除目标插件 Binaries、Intermediate 后，用 Rider 的目标工程 Editor / Development 配置重新编译两个模块。
5. 在目标 DA_WardrobeMenu 的 Levels 追加地图 /Game/BluePrint/ALS/Maps/L_ALSFirstDemo（或自己的地图），保留自己的相机/人物与声音配置。Menu Level 指向自己的展示关卡。
6. 打包设置把自己的目的地地图加入 MapsToCook，并添加 DirectoriesToAlwaysCook=/Game/BluePrint/ALS。见 ConfigFragment.ini。
7. 打开新示例关卡验证。原展示关卡继续使用 WardrobeMenuGameMode。开始游戏会传入 BP_ALSGameMode 覆盖。

## 范围与兼容性
第一版是基础第三人称走/跑，不是整套 ALS V4 移植。通过实际速度驱动待机/走/跑混合，含脚步同步、加减速、转向、碰撞、台阶、斜坡、镜头避障和暂停返回。
新角色保留 MMD 常规骨骼层级，使用独立 SK_DaniyaALS_Skeleton。不会覆盖展示角色或把旧交互动画强行换到新骨骼。
头发和裙摆由 KawaiiPhysics 处理，导入动画中对应的轨道已移除。细节碰撞与衣摆参数仍可以在动画蓝图继续美术调整。
本机旧 L_WardrobeMain 和部分模型资源存储 UE5-Main 自定义版本124，官方引擎支持123，旧关卡不能在本次官方引擎测试运行。这个包不修改旧 uasset 的版本号；新 ALS 示例与资源可正常运行。使用原自改引擎打开旧资源，或另外解决资源版本兼容。
